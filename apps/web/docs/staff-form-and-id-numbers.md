# Staff form fixes, automatic ID numbers and student discard warning (21 Nov 2026)

Owner-requested functional changes. They touch server, shared schemas and Prisma, so they sit outside the Hills
"looks only" rules. See "Gate note" at the end.

## What was done

### 1. Contract end date (staff form)
- **Cause of the old behaviour:** an empty date box is sent as `''`, which failed the `YYYY-MM-DD` check even though the
  label said "optional".
- **Rule now:** full-time staff are employed indefinitely and have **no** end date. Part-time, contract and temporary staff
  **must** have one. The field only appears for those three types and is labelled "Contract end date".
- Shared rule: `contractExpiryRequired()` in `packages/shared/schemas/hr.ts`, used by the form, the create schema and
  `hrService.updateStaff`. Switching a person to full-time clears the stored date. The staff card shows "Indefinite" for
  full-time staff.
- On edit, the server only enforces the rule when the edit touches employment type or end date, so unrelated edits do not
  trip over older records. Older part-time staff with no date will be asked for one the next time they are edited in the form.

### 2. Teaching-only details
- **Subjects qualified to teach, TCM registration / licence / expiry and training route** now appear only when
  "Teaching staff" is ticked (create form, edit form and staff card).
- Server: marking someone as not teaching clears their TCM details, training route and subjects. Creating a non-teaching
  member ignores them. HR analytics already only read teachers.
- "Training load" in the request was read as **Training route** (the only matching field).

### 3. Highest qualification and programme
- Highest qualification is shown for every member of staff.
- Choosing **Diploma** or **Degree** shows "Programme studied" (e.g. Bachelor of Education). It is required when
  creating staff, and shown on the staff card ("Programme studied"). Other levels clear it.
- New column `staff_profiles.qualificationProgram` (migration below).

### 4. Removed: "Qualified in education" and "Housing"
Removed everywhere: form, card, API types, zod schema, service, route key list, constants (`HOUSING_STATUSES` etc.),
Prisma model fields and the `HousingStatus` enum. No data had been recorded in them.

### 5. National ID required on create
`nrbNumber` is required when creating staff ("National ID number is required"). Editing does not force it, so older
records without one can still be edited.

### 6. Automatic employee and registration numbers
- **Employee numbers** are now generated by the server (`hrService.createStaff`); the manual field is gone from the form.
- **Student registration numbers** were already automatic (fixed `SMS-YYYY-NNNN`); they now follow the configured layout.
- **Layout is set in Settings, "ID numbers"** (admin, HR, high rank). Rules (one source of truth:
  `packages/shared/constants/malawi/registration.ts`):
  - Write the number as it should look, with zeros where the running number goes: `EMP-{YYYY}-000` gives
    `EMP-2026-001`, `EMP-2026-002`.
  - The **last run of zeros** is the running number; its length is the minimum width. It grows rather than overflows
    (`...999` is followed by `...1000`).
  - `{YYYY}` / `{YY}` become the year the record is created, so the count restarts at 1 each new year.
  - Everything else is copied as typed. Allowed characters: letters, digits and `- _ / .`
  - The next number is one more than the highest already issued in the **same layout**; the first is 1.
  - Existing numbers are never changed; only new records follow a new layout.
- Defaults: staff `EMP-{YYYY}-0000`, students `SMS-{YYYY}-0000` (students keep their current look until changed).
- Concurrency: a clash on the unique column recomputes and retries (5 attempts), for staff as for students.
- Stored as two settings keys: `hr_employee_no_format`, `student_registration_no_format`. API: `GET/PATCH /settings/id-numbers`.

### 7. Student form: unsaved-changes warning
The student form now asks "Keep editing / Discard changes" (same component wording and rules as the staff form,
`src/lib/hills/unsaved.ts`) when the X, an outside click or Escape is used after anything was entered (typed or picked
fields, photo, welfare). An untouched form closes at once. The footer Cancel and the close after a successful save behave
as before, exactly as in the staff form. Works for the phone sheet and the desktop dialog.

## Decisions made (from the owner's answers)
1. Contract end date required for part-time, contract and temporary; never for full-time.
2. ID format is free text (not fixed to "EMP"); `{YYYY}` supported so the year rolls over by itself.
3. Existing numbers untouched; only new records follow the layout.
4. Admin, HR and high rank can edit the formats (one permission set for both staff and student layouts).
5. Programme field for Diploma and Degree only (not Postgraduate, not Other).
6. National ID required on create, not forced on edit.
7. "Qualified in education" and "Housing" removed completely, including the database.

## How to deploy
1. Apply the migration (`prisma migrate deploy`). It adds one nullable column and drops two unused columns and one enum.
2. Regenerate the Prisma client (`prisma generate`) before building.
3. Optional: set the layouts under Settings, "ID numbers". Until then the defaults above apply.

## Not tested here
No packages could be installed in the working environment, so the app was not built, type-checked or run. What was checked:
every changed file parses; the ID format helpers were run in Node against the examples (EMP-24-000, `{YYYY}`, suffixes,
overflow, invalid formats). Please run `pnpm typecheck`, the tests and a manual pass: create full-time and contract staff,
create a teacher and a non-teacher, edit a teacher to non-teacher, create a staff member and a student twice in a row
(numbers must count up), change the layout and create another, and close the student form after typing.

## What remains / open questions
- **Gate note:** `tools/hills/logic-allowlist.json` freezes `src/server/**`, `prisma/**` and `packages/**` for the theme
  work. These changes are owner-approved but are not declared there, so `pnpm hills:logic-diff` will flag them. Either add
  `approvedFrozen` entries (approved 2026-11-21) or rebase the gate's baseline.
- Older part-time/contract staff with no end date, and older diploma/degree holders with no programme: the form asks for
  these only when the staff member is edited (programme only on create).
- Employee numbers issued before this change (for example `EMP-014`) do not match the new layout, so they are ignored
  when counting and the first number in the new layout is 1. To continue from an old number instead, the format would
  need a starting-number option; not built because it was not asked for.
- The student form now closes on Escape (it did not before), to match the staff form.
